# Quality check, 2026-11-01

The ten engineering rules, checked against the code on `main`, with the evidence. Run on Windows 11,
JDK 21.0.12, Maven 3.9.11.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | fixed | The only network call is `TraceFetcher.fetch`. It had a 30 s connect timeout and a 10-minute request timeout, but Java's request timeout stops at the response headers, so a body that stopped sending would block `read` forever. A watchdog now closes the body when the 10-minute deadline passes, and the download fails with `did not finish within PT10M` (`trace/TraceFetcher.java`, test `aBodyThatStallsIsAbandonedAtTheDeadline`). No retries, so nothing to bound. No empty `catch`: all 11 `catch` blocks in `src/main` rethrow, report or restore the interrupt flag. `scripts/osv_audit.py` uses a 60 s timeout. |
| 2 | Writes safe to retry | fixed | Trace downloads go to `<name>.part`, which is renamed with `ATOMIC_MOVE` only after the size and SHA-256 match. A second fetch re-hashes the file and does not download again (`downloadsThePinnedBytesOnceAndReusesThemAfterwards`: one HTTP request for two fetches). `ResultsTable.write` wrote the file in place, so a crash could leave half a table behind for `--expect`. It now writes `<file>.part` and renames it atomically (`writeThenReadGivesTheSameRows` checks the replace and that no temporary file is left). |
| 3 | No race conditions | pass | Single-threaded replay. The policies are not thread-safe and are documented as single-owner. The only other thread is the fetch watchdog, and the state it shares is an `AtomicBoolean` plus `InputStream.close`, which the JDK makes safe to call from another thread. |
| 4 | Don't trust the clock | pass | The only timings are `System.nanoTime` deltas (`cli/Main.java`, replay seconds). The watchdog uses `CompletableFuture.delayedExecutor`, which is backed by `nanoTime`. No timestamps are stored. Results do not depend on time. |
| 5 | Read before changing | pass | No environment variables are read. Every path in the README exists (`traces/pins.tsv`, `docs/...`, `scripts/osv_audit.py`). `MVNLOCAL` in the Makefile is documented there. Before relying on `HttpResponse` body-close behaviour, I read the JDK 21 source of `ResponseSubscribers.HttpResponseInputStream`: `close()` offers the last buffer, so a blocked `read` wakes and throws. |
| 6 | Never break compatibility | pass | The results TSV header and fields are unchanged. `TraceFetcher()` keeps its public constructor; the deadline constructor and URL overload are package-private. |
| 7 | One source of truth | pass | The vendored sketch names its source (ADR 0003). Downloaded traces are rebuilt from `traces/pins.tsv` and checked by size and SHA-256. The committed table `docs/results/m1-hit-rates.tsv` is the single expected result that `--expect` gates on. Java 21, JUnit 6.1.3 and the plugin versions in the README and `docs/results/m1.md` match `pom.xml`. |
| 8 | Small changes, no secrets, validate input | pass | `grep -riE "(api[_-]?key|secret|token|password)\s*[:=]"`: no matches. The CLI rejects unknown or repeated options, bad sizes, too many items and unknown policies or modes (exit 2). Pins are checked for name, scheme, host, port, query, size and hash. Lines are capped at 4,096 bytes and results files at 100,000 lines. No new dependency: the tests use the JDK's built-in `com.sun.net.httpserver`. |
| 9 | Tests that can actually fail | fixed | No `@Disabled`, no assumptions, no `assertTrue(true)`. Mutation check below: 3 of 12 new mutants survived, and each now has a test that kills it. |
| 10 | Re-verify | pass | `mvn -B verify`: `Tests run: 108, Failures: 0, Errors: 0, Skipped: 0` (Enforcer, Spotless, `-Xlint:all -Werror` included). End to end on cluster045: `RESULT traces=1 cells=25 above_infinite=0 expected=match best_at_size=arc:5`. ## Tests added (100 -> 108)

- `TraceFetcherTest` (5): download from a loopback HTTP server, one request for two fetches. A
  stalled body is abandoned at a 1 s deadline. A body larger than the pin is cut off. Bytes with the
  wrong digest are never renamed into place. HTTP 404 and an unfollowed 302 fail without leaving a
  file.
- `CeilingCheckTest` (2): cells at or below the never-evicting cache pass; a cell above it, or one
  with a different read count, is reported.
- `ReplayerTest.acceptsAGridOfExactlyTheLaneLimit`: 5 policies x 40 sizes = 200 lanes is accepted
  (41 sizes was already rejected).

## Known limitations

None new. M2 and M3 work (byte hit rate, S3-FIFO, scan-heavy trace) is unchanged and listed in the README roadmap.
